## 实际跑通的学习验收链路

1. 从官方 Kaggle 端点下载并校验 Olist 压缩包 SHA-256：`967e41e04fc306fe604e2a693f488995a8b41e5047418f8a5c8e4abd6deca784`。
2. 导入 9 张 CSV；校验得到 99,441 个订单、112,650 个订单行、99,224 条评价、103,886 条支付和 1,000,163 条地理记录，重复主键与孤儿引用均为 0。
3. 以 `2016-10-04 00:00:00` 启动回放，读取筛选快照，开始回放、暂停、复位，并确认暂停后源时间不再变化。
4. 对同一可信快照分别提出配送与评价问题，得到不同的、带 `sourceLocalNow` 的事实绑定回答。
5. 生产入口 `pnpm start` 在隔离端口返回 `/healthz` 200，并附带 CSP、`X-Content-Type-Options` 和 `X-Request-Id`。

## P0：进入真实企业环境前必须完成

1. **替换学习数据与接入层。** Olist 为 CC BY-NC-SA 4.0 的匿名历史公开数据，只能作开发/验收样本。真实系统需要从 OMS、支付、WMS/物流、退款/售后、商品和广告系统获取带事件时间、来源、幂等键与数据契约的事实流。
2. **补齐支付与售后事件。** 当前历史回放已隐藏没有发生时间的支付/取消事实；要向业务用户提供支付、退款与结算分析，必须接入带事件时间、状态与金额的支付/售后流水。
3. **性能改造。** CSV 导入改为流式批量写入；把快照指标做日级预聚合/缓存或异步作业，先设定并验证 p95 响应预算后才允许轮询。
4. **建立身份与数据边界。** 接入企业 IdP、RBAC、租户/组织范围过滤、不可篡改审计日志、密钥托管、加密备份和恢复演练。它们依赖企业身份与数据治理决策，不能由本地项目凭空替代。
5. **上线工程。** 在 CI 中固定 Node 24、依赖锁文件、单元/集成/E2E、镜像扫描、SBOM、迁移和回滚；部署在 TLS 反向代理后，配置监控、日志采集、告警与值班响应。

## 已核验的开源参考与复用边界

- CoreUI 免费 React 管理模板：MIT，固定提交 `1c09f27ef436a1e358be5d10daf3b1f27f2e20a6`；应用壳层已按 `THIRD_PARTY_NOTICES.md` 归属。
- `seajoyer/olist-ecommerce-analytics`：MIT，固定提交 `af09e7e6aa5753ce75887882d7749ef5c3a8f48b`；只借鉴经营域划分（经营、客户、商品与运营），不复制其会将订单行与支付行直接连接而放大金额的 SQL。
- Helmet、Pino、express-rate-limit：均采用已核验的 MIT 依赖版本，分别用于安全响应头、结构化日志与 API 限流。
- Apache Superset、OpenTelemetry Demo、Saleor：仅作为产品能力/运维流程参考，不嵌入不兼容的服务端源码。
