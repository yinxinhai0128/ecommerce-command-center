# Olist 真实数据回放试点设计

## 1. 目标

在不依赖企业店铺、ERP、云服务器或付费数据平台的前提下，为现有电商经营驾驶舱增加一个可审计的“真实匿名历史数据回放”模式。

试点使用 Olist 发布的约十万笔真实匿名电商订单。系统必须证明以下最小闭环：

1. 数据来自可追溯的公开来源，而不是项目内生成器。
2. 原始数据能够重复导入并与源文件对账。
3. 所有试点指标由服务端基于可信数据计算。
4. 历史订单可按虚拟时钟回放，驾驶舱随服务端状态更新。
5. 智能分析只接收用户问题和筛选条件，由服务端查询当前可信快照。
6. 页面明确说明这是历史数据回放，不能被误认为某家企业的实时生产数据。

## 2. 使用边界与许可证

- 数据来源：Olist 在 Kaggle 发布的 Brazilian E-Commerce Public Dataset。
- 许可证：CC BY-NC-SA 4.0。
- 用途：仅限个人学习、演示和作品集，不用于商业产品或企业生产经营。
- 归属：README 和试点页面必须标注数据来源、许可证及 Olist 署名。
- 原始 CSV、下载压缩包和生成的数据库不进入 Git；仓库只保存下载/导入代码、测试夹具和来源说明。
- 不从许可证不明的 GitHub 镜像下载数据。自动下载失败时，提示用户从官方 Kaggle 页面下载压缩包后运行本地导入命令。

## 3. 范围

### 3.1 本期包含

- 保留现有“模拟演示”模式。
- 新增“真实数据试点”模式和明确的数据来源标识。
- 下载、校验和导入 Olist CSV。
- 本地 SQLite 持久化和导入清单。
- 服务端指标查询 API。
- 服务端虚拟回放时钟、开始、暂停和重置。
- 前端轮询服务端快照并展示真实支持的指标。
- 日期、类目、卖家和客户州筛选。
- 基于服务端可信快照的结构化分析和问题相关的本地降级。
- 单元、集成、浏览器及完整数据对账测试。

### 3.2 本期不包含

- 企业真实店铺、ERP、CRM 或广告平台连接器。
- 公网部署、SSO、RBAC、多租户或企业审计系统。
- Kafka、Flink、CDC 或真正的在线事件流。
- Olist 数据不具备的库存、成本、毛利、访问流量、广告 ROI、退款金额和企业目标。
- 将 Olist 和 Google GA4 样本拼接成同一家企业的数据。
- 机器学习预测模型。
- 商业化或重新分发 Olist 原始数据。

## 4. 方案比较与选择

### 方案 A：现有模型强制映射

把 Olist 数据映射为当前 `CommerceDataset`，缺失字段填零。

优点是前端改动少；缺点是会把“未知”伪装为零，并把卖家误标成店铺、履约漏斗误标成访问转化。该方案不采用。

### 方案 B：独立试点数据契约，复用视觉组件

新增 Olist 试点服务端契约和试点页面，复用现有 `Panel`、`MetricValue`、图表风格与分析结果组件。模拟模式不改变，用户通过数据源开关进入试点。

优点是口径诚实、对原功能回归风险小，并为未来真实企业数据源建立服务端边界；代价是增加一组专用类型和组件。采用此方案。

### 方案 C：立即重构为通用指标平台

一次性抽象所有数据源、指标语义层和动态组件。

长期结构最完整，但超出最小试点，容易产生没有第二个真实数据源验证的过度抽象。该方案不采用。

## 5. 总体架构

```text
Olist 官方压缩包
  -> 下载清单与 SHA-256
  -> CSV 校验和事务导入
  -> var/olist/olist.sqlite
  -> PilotRepository
       -> 指标快照 API
       -> 回放控制 API
       -> 可信分析上下文
  -> React 真实数据试点页面
```

现有模拟模式继续使用浏览器内的 `DashboardProvider`。试点模式使用新的 `PilotDashboardProvider`，所有经营结果从 `/api/pilot/*` 获取，前端不得重新计算 GMV 等指标。

## 6. 数据存储与来源清单

### 6.1 本地目录

```text
var/olist/
  source.zip
  raw/
  manifest.json
  olist.sqlite
```

`var/` 整体加入 `.gitignore`。

`manifest.json` 保存：

- 官方来源 URL
- 数据集 slug
- 许可证
- 下载时间
- 压缩包 SHA-256
- 每个已导入 CSV 的 SHA-256
- 每张表的源行数和已导入行数
- 数据集最早和最晚订单时间
- 导入程序版本

### 6.2 导入表

本期导入以下文件：

- `olist_orders_dataset.csv`
- `olist_order_items_dataset.csv`
- `olist_order_reviews_dataset.csv`
- `olist_products_dataset.csv`
- `olist_customers_dataset.csv`
- `olist_sellers_dataset.csv`
- `product_category_name_translation.csv`

地理坐标文件不导入；客户和卖家 CSV 已包含本期所需的城市及州信息。

### 6.3 导入保证

- 导入在单个数据库事务中完成。
- 每张表使用 Olist 业务主键或复合主键保证幂等。
- 缺文件、缺必需列、时间非法、金额非法或外键引用失败时整体回滚。
- 只有全部校验和对账通过后，manifest 才标记 `ready: true`。
- 重复导入同一数据集后，表行数和汇总金额保持不变。

## 7. 试点指标口径

所有日期筛选按 `order_purchase_timestamp` 选择订单队列，结束时间包含当日末尾并受回放虚拟时间上限约束。

Olist 时间字段没有时区偏移。本期保留其原始本地墙上时间，并以同一无时区规则完成排序、筛选和时长计算；API 和页面统一标注“源数据本地时间”，不擅自换算成北京时间或推定的巴西时区。

### 7.1 核心指标

- 商品成交额：非 `canceled`、非 `unavailable` 订单的 `order_items.price` 之和，不含运费。
- 有效订单量：上述有效状态的去重 `order_id` 数。
- 客单价：商品成交额除以有效订单量，零订单时为零。
- 取消率：`canceled` 订单数除以全部下单订单数；`unavailable` 单独作为不可履约，不混入取消率。
- 准时送达率：已送达订单中，`order_delivered_customer_date <= order_estimated_delivery_date` 的比例。
- 平均配送时长：已送达订单从购买到客户签收的平均自然日数。
- 平均评价分：筛选订单所关联评价的 `review_score` 平均值。

### 7.2 履约漏斗

漏斗按同一购买队列累计统计：

1. 已下单：存在购买时间。
2. 已批准：存在批准时间。
3. 已交承运商：存在承运商收件时间。
4. 已送达：存在客户签收时间。

它必须命名为“订单履约漏斗”，不得标注为访问或支付转化漏斗。

### 7.3 排行与明细

- 类目排行：按英文翻译类目聚合商品成交额。
- 卖家排行：按 `seller_id` 聚合商品成交额。
- 客户地区排行：按客户州聚合商品成交额。
- 最近订单：返回订单 ID、购买时间、状态、商品金额、客户州和商品件数。

### 7.4 不支持的指标

库存、毛利、访问转化、广告 ROI、退款金额、目标达成和销售预测在试点模式中不显示为零，而是完全不渲染，并在“数据能力说明”中列为当前来源不支持。

## 8. 回放模型

- 回放状态由服务端维护并持久化到 SQLite，不由浏览器生成事件。
- 初始虚拟时间设为数据集最早订单时间后第 30 天，使默认 30 日窗口有可见数据。
- 运行时每 3 秒推进 6 个历史小时。
- 默认查询窗口为虚拟时间结束前 30 天。
- 暂停后虚拟时间不再推进；刷新浏览器不会改变回放状态。
- 重置恢复到初始虚拟时间和运行状态。
- 到达数据集末尾后自动暂停，不循环伪造新订单。
- 指标变化来自虚拟时间纳入更多真实历史记录，而不是修改原始订单。

## 9. 服务端 API

### 9.1 状态与元数据

`GET /api/pilot/status`

返回数据是否就绪、来源、许可证、数据周期、虚拟时间、运行状态、最后更新时间和支持能力。

数据未导入时返回 `200` 和 `ready: false`，附带官方来源与本地导入命令；模拟模式仍可运行。

### 9.2 筛选选项

`GET /api/pilot/filter-options`

返回类目、卖家和客户州选项。卖家只返回匿名 ID，不推断企业名称。

### 9.3 指标快照

`GET /api/pilot/snapshot?start=&end=&category=&sellerId=&customerState=`

服务端校验日期、日期顺序、选项值和最大查询跨度。响应包含：

- 当前筛选条件
- 虚拟时间和数据新鲜度
- 核心指标及对比期
- 日趋势
- 履约漏斗
- 三个排行
- 最近订单
- 数据能力说明

### 9.4 回放控制

`POST /api/pilot/replay`

请求体为 `{ "action": "start" | "pause" | "reset" }`，返回更新后的回放状态。

### 9.5 智能分析

`POST /api/pilot/analysis`

浏览器只发送 `{ question, filters }`。服务端重新查询当前快照，构造包含口径、虚拟时间、KPI、趋势变化和排行贡献的可信上下文。

- 配置 DeepSeek Key 时调用现有结构化分析服务。
- 未配置或调用失败时使用问题相关的本地规则分析。
- 本地规则至少区分经营表现、取消问题、配送问题、评价问题和头部贡献五类问题。
- 响应复用现有 `AnalysisResult` 结构并明确 `source` 与降级原因。
- 所有数值证据必须来自本次服务端快照；模型返回的数值如无法在快照允许值中匹配，则拒绝该响应并降级。

## 10. 前端交互

- 页头增加“模拟演示 / 真实数据试点”数据源选择。
- 选择真实试点后，保留“实时监控 / 智能分析”两个主标签。
- 页面固定展示“真实匿名历史数据回放”标识、Olist 署名、虚拟时间和许可证入口。
- 试点实时监控页仅使用试点支持的卡片与面板，复用现有浅色克制视觉系统。
- 筛选项改为日期、类目、卖家和客户州，并由服务端提供选项。
- 每 3 秒轮询状态和快照；暂停时仍允许用户手动刷新筛选，但虚拟时间不推进。
- 数据未导入时展示一页可执行的导入说明，不抛出空白页。
- API 失败时保留最后一次成功快照，显示错误和重试按钮。
- 智能分析显示回答使用的数据虚拟时间；快照变化后标记旧回答已过期。

## 11. 错误处理

- 官方下载失败：保留现有文件，不覆盖 manifest，输出手动下载路径。
- 压缩包或 CSV 校验失败：事务回滚并删除本次临时数据库，不删除上一次可用数据库。
- 数据未准备：试点 API 返回结构化未就绪状态，不影响模拟模式。
- 查询参数非法：返回 `400`，不执行 SQL。
- 数据库不可读：返回 `503` 和稳定错误码，前端保留旧快照。
- DeepSeek 超时或响应非法：降级到基于同一可信快照的本地规则分析。
- 浏览器离开试点模式：停止轮询并取消未完成请求。

## 12. 测试设计

### 12.1 小型测试夹具

仓库提交一组自建的最小 CSV 夹具，不复制 Olist 原始记录。夹具覆盖：

- 多商品订单
- 正常、取消、不可履约和已送达状态
- 准时与逾期送达
- 多类目、卖家和州
- 有评价与无评价订单
- 日期和金额边界

### 12.2 自动化测试

- 下载清单和 SHA-256 生成测试。
- 导入成功、缺文件、缺字段、回滚、幂等和外键测试。
- 每个指标的手算测试。
- 筛选、对比期和回放时间上限测试。
- 回放开始、暂停、重置、到达末尾和重启恢复测试。
- API 参数验证、未就绪、数据库故障和稳定错误码测试。
- 本地分析问题相关性测试：不同问题必须返回不同且相关的证据。
- DeepSeek 数值越界时降级测试。
- React 数据源切换、未导入、加载、失败、重试和旧快照测试。
- Playwright 验证真实模式、回放数值变化、暂停稳定和智能分析证据。

### 12.3 完整数据验收

官方数据导入后执行独立验收命令，检查：

- 每张表导入行数等于对应 CSV 数据行数。
- 数据库业务主键无重复。
- 订单明细引用的订单、商品和卖家均存在。
- 数据库商品成交额与源 CSV 按相同口径计算的结果一致。
- 重复导入后行数和成交额不变。
- 数据集最早和最晚订单时间与源文件一致。

## 13. 命令与配置

计划提供以下命令：

```text
pnpm data:olist:download
pnpm data:olist:import [压缩包或解压目录]
pnpm data:olist:verify
pnpm dev
pnpm test
pnpm e2e
```

可配置项仅包含：

- `OLIST_DATA_DIR`：默认 `var/olist`。
- `PILOT_REPLAY_TICK_MS`：默认 `3000`，测试中使用依赖注入而不是环境变量改写。
- 现有 `DEEPSEEK_API_KEY` 和 `PORT`。

不新增云服务或 Docker 前置条件。项目继续要求 README 所声明的 Node.js 主版本。

本地数据库使用该 Node.js 版本自带的 `node:sqlite`，不引入需要本机编译的原生 SQLite 驱动。CSV 和 ZIP 仅允许增加纯 JavaScript 依赖。

## 14. 验收标准

1. 用户未导入 Olist 数据时，模拟驾驶舱正常运行，真实试点给出清晰导入指引。
2. 官方数据导入后，页面明确标记来源、许可证和历史回放性质。
3. 所有真实模式指标均由服务端 SQLite 查询生成。
4. 导入行数、主键和商品成交额通过完整数据对账。
5. 同一数据重复导入不会增加行数或改变指标。
6. 运行回放后虚拟时间和指标随真实历史订单推进；暂停后保持稳定。
7. 日期、类目、卖家和客户州筛选在所有试点模块使用同一口径。
8. 页面不展示来源不支持的库存、毛利、访问转化、广告 ROI、退款金额、目标和预测。
9. 不同经营问题得到问题相关的分析，本地降级不再忽略问题。
10. 原有模拟模式测试、类型检查和构建继续通过。
11. 试点单元、集成和浏览器测试通过，浏览器无相关错误。
12. Git 中不包含 Olist 原始数据、生成数据库、密钥或用户本地 `.env`。

## 15. 后续生产迁移边界

本期接口以服务端数据源为边界，未来真实企业接入可用 PostgreSQL、ClickHouse 或现有数仓替换本地 SQLite。Olist 专用的表结构、口径和页面不会被包装成通用企业语义层；只有在出现第二个真实数据源后，才提炼公共数据源接口和指标模型。
