# 经营驾驶舱

一个用于演示电商经营数据的本地 React 应用。它包含两个一级模块：**实时监控** 与 **智能分析**。数据、商店、商品和客户均为模拟数据，不对应真实商家或客户。

## 运行

```powershell
pnpm install
pnpm dev
```

`pnpm dev` 会同时启动 Vite 前端（`http://127.0.0.1:5173`）和 Express 分析服务（默认 `http://127.0.0.1:8787`）。

常用命令：

```powershell
pnpm test
pnpm build
pnpm e2e
pnpm screenshots
```

需要 Node.js 24 或更高版本；开发服务使用 Node 的 `--env-file-if-exists` 支持读取可选 `.env`。`pnpm e2e` 只运行核心流程，不会改写交付截图；需要明确刷新截图时运行 `pnpm screenshots`。

## 分析服务配置

使用 PowerShell 复制环境变量模板：

```powershell
Copy-Item .env.example .env
```

`.env` 支持以下变量：

```text
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-v4-flash
PORT=8787
```

API Key 只由 Express 服务端读取，浏览器不会接收或保存它。未配置 `DEEPSEEK_API_KEY` 时，智能分析会返回本地模拟分析结果；这使完整界面和问答流程无需 Key 也能运行。

## 经营口径

- 单日范围与昨日同期对比；2–7 日范围与前 7 天对比；更长范围与前 30 天对比。
- GMV 是已支付或已完成订单的商品金额、运费与优惠后的合计；净销售额为 GMV 减已批准或已完成退款。
- 转化率为去重支付买家数除以筛选范围内访客数；退款率为退款金额除以 GMV；目标达成率为 GMV 除以同一范围目标金额。
- 未来 7 天预测使用历史周度基线与近期趋势；实时数据每 3 秒模拟一次订单或退款事件，暂停后停止该模拟更新。

## 架构与数据边界

前端在浏览器中从模拟数据生成筛选后的快照，并把最小的结构化 JSON 上下文提交到 `POST /api/analysis`。上下文只包含日期范围、KPI、贡献项、告警和预测；服务端返回同样为结构化 JSON 的结论、信号、归因、风险、行动建议与追问。服务端优先使用已配置的模型，缺失 Key 或上游异常时使用本地模拟分析。

## 智能分析评测（P0-6）

分析能力有可复现的验收标准，不靠肉眼感觉：

- 评测集：[`evals/analysis_cases.json`](evals/analysis_cases.json) — 覆盖 GMV 变化、退款异常、转化下降、库存风险、目标进度、渠道归因、客单价、净销售/毛利 8 类经营问题
- 判定维度：指标是否被提及（中英文别名）、summary 是否包含来自结构化上下文的真实数字（防幻觉）、归因必须带证据、行动建议必须有负责人与验证指标、回答结构完整
- 运行：`pnpm eval:analysis`（离线，无需 API Key）；报告落盘 `evals/reports/`
- **实测结果（2026-08-24）：8/8 = 100% 通过**；数据质量检查 14 项全部通过

在原有"实时监控 + DeepSeek 分析"骨架上完成以下改造（对照预案 P0）：

1. **指标口径文档**（`docs/metrics.md`）：8 个 KPI 的公式、粒度、计入条件、边界处理与代码实现逐一核对；异常检测规则的基准期、阈值、影响金额算法文档化
2. **数据质量层**（P0-2）：新增 `dataQuality.ts`——14 项检查覆盖主键唯一、外键完整、金额非负、状态合法、时间逻辑；结果通过 `DataQualityBanner` 直接暴露在看板头部，检查不过时指标不可信
3. **本地分析增强**：`localProvider` 原先对任何问题只输出 GMV 模板；现按问题关键词匹配相关 KPI 并以真实上下文数值作答
4. **分析评测集与批量执行器**（P0-6）：`pnpm eval:analysis` 离线可跑，含防幻觉断言与固定回答结构校验
5. **CI 修复**：requirements.lock 补 Linux 平台 uvloop hash pin；提交 router 重构修复 JSX namespace 构建失败

## 已知限制

- 数据为模拟生成，预测与告警仅演示机制，不构成真实经营结论
- 未配置 `DEEPSEEK_API_KEY` 时为规则式模拟分析，回答深度有限（但有评测集兜底其结构与真实性）
- 异常检测阈值（如退款率 +30%/8%）为经验值，未做分行业校准
- 移动端布局非主验证范围

## 2 分钟演示脚本

1. 打开首页 → 指出顶部绿色"数据质量检查通过"横幅：所有指标可信的前提（30s）
2. 实时监控页 → KPI 卡片与分钟脉冲：说明 GMV 口径与昨日同期对比逻辑（30s）
3. 触发一条退款率异常（或直接看告警栏）→ 展示 evidence + 影响金额算法（30s）
4. 切到智能分析 → 问"退款率最近有没有异常？" → 回答中的数字可在上方 KPI 中找到对应来源（30s）
5. 终端运行 `pnpm eval:analysis` → 展示 8/8 通过的报告，强调"防幻觉断言"（30s）
